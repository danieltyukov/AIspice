aispice is an open-source agent that edits LTspice schematics, simulates them with ngspice, LTspice or Xyce, and checks the results against your specs.

It runs on your own machine as a desktop app, a command-line tool, or an MCP server inside the coding agent you already use. ngspice is enough to start. LTspice and Xyce are used when they are installed.

  • Linux AppImage
  • Linux .deb
  • Windows .exe
  • macOS .dmg 
cargo install --locked --git https://github.com/danieltyukov/aispice aispice

The command line tool on its own, built from source with Rust 1.88 or newer. Prebuilt binaries for each platform, and every older version, are on the releases page.

How it works

  1. Open a folder of .asc files Any folder with LTspice schematics in it. aispice works inside that folder and refuses any path outside it.
  2. Ask in plain language “Set the gain to 10 and keep the overshoot under 5 %.” “Why does this regulator ring at light load?”
  3. The agent edits with typed operations Add a part, set a value, connect two pins by name. It never writes raw coordinates, so a wire cannot land a grid step off its pin.
  4. It simulates and measures The run goes to ngspice, LTspice or Xyce, and every number it reports is measured from the resulting waveforms.
  5. It checks your specs Each line of your spec table is measured and shown as pass or fail, with the margin.
  6. Every edit can be undone Each change comes with a diff of what moved and what changed value, and one click puts the file back.

What it can do

Edit and wire
Place, move, rotate and remove parts, set values and connect pins. The router will not draw a wire that shorts two nets.
Simulate
ngspice, LTspice (native or under Wine) and Xyce on your machine, and Spectre on a remote server over SSH. Netlists are translated for each one.
Measure
Bandwidth, phase and gain margin, overshoot, settling, rise and fall time, THD, RMS, crossings and the value at any point.
Check specs
Write the limits once as a table of measurements and bounds. Every run is checked against it, row by row, pass or fail.
Sweep and test robustness
Parameter sweeps, Monte Carlo yield over component tolerances, and the worst case against your specs.
Size
The model picks which values to tune and their ranges. A numerical optimizer searches them with the simulator in the loop.
Draw from a netlist
Give it a SPICE netlist and it places and wires a readable LTspice schematic.
Electrical rule checks
No ground, floating pins, dangling wires, shorted or parallel sources and nets with no DC path are reported before anything runs.
Poles and zeros
Pole-zero analysis of a transfer function, to see why a loop rings before you start tuning it.
Schematic from an image
A screenshot or photo of a schematic becomes a netlist you can simulate, with a model that accepts images.

Three ways to use it

Desktop app
The circuit list, the schematic, waveforms with cursors, the netlist and a chat with the agent in one window. Each tool call shows up as a card with its numbers and, for an edit, the diff and an undo button.
Command line
aispice sim runs a schematic, aispice check evaluates a spec table and exits non-zero when a row fails, so it can gate a CI job, and aispice chat talks to the agent from the terminal.
MCP server
aispice mcp gives Claude Code, Cursor, Codex, Claude Desktop or any other MCP client the same tools the app uses, over stdio.

Run once. Add -s user to make it available in every project.

claude mcp add aispice -- aispice mcp

In ~/.cursor/mcp.json or claude_desktop_config.json, then restart the app.

{
  "mcpServers": {
    "aispice": {
      "command": "aispice",
      "args": ["mcp"]
    }
  }
}

Run once. It writes the entry to ~/.codex/config.toml.

codex mcp add aispice -- aispice mcp

If a desktop client cannot find aispice, give the full path to the binary as the command.

Models

Use any provider you have a key for: Anthropic, OpenAI, Google, OpenRouter, Ollama, or any endpoint that speaks the OpenAI chat completions API, such as LM Studio or vLLM. The model list is fetched from the provider when you open the picker, so a new model shows up without an aispice update.

Keys are stored in the operating system's keychain (Secret Service, Keychain or Credential Manager), not in a plain-text config file.

Privacy

  • Runs locally. There is no account, no sign-up and no telemetry.
  • The only network requests go to the model provider you pick. Circuit text and simulation results are sent there as part of the conversation, and nowhere else.
  • With a local model through Ollama, nothing leaves your machine.
  • The agent's tools are confined to the folder you opened.

Questions

Do I need LTspice?

No. ngspice works out of the box. When LTspice is installed, aispice uses it for netlisting and simulation, and reloads the schematic in LTspice after an edit.

Does it work on Linux?

Yes. LTspice runs under Wine and aispice finds it there, or you can use ngspice or Xyce natively.

Which models work best?

Frontier models with tool calling do the best work on multi-step design tasks. Local models through Ollama are fine for smaller jobs such as reading a schematic, changing a value or running a simulation.

Is it affiliated with Analog Devices?

No. aispice is an independent open-source project. LTspice is a trademark of Analog Devices, Inc.

Can it use my PDK?

Yes, through Spectre over SSH: simulations run on your own server with your own models. aispice never copies model files off that server.
